# Changelog

All notable changes to afo-mcp. The latest release highlights are in the [README](README.md#-whats-new--v100--first-release); earlier ones in [WHATS_NEW.md](WHATS_NEW.md).

## [1.0.0] — unreleased

The first version: reading, building and operating Analysis for Office workbooks.

### Added — Read

- **One workbook, completely** — `afo_read_workbook` reads the AfO definition from the hidden sheet without Excel or a logon: settings and connection, data sources with their stored navigation state (filters with hierarchy nodes and exclusions, axes, hierarchies, variable values), planning functions and sequences with data source, aggregation level, filter, variables and the cells variables are read from, crosstabs and formula items with their ranges, SAP cell formulas with parsed arguments, VBA modules with procedures and the AfO API calls in them, and buttons with their macros. Links that do not resolve come back as issues: an alias no data source has, a button whose macro is missing, a crosstab without its data source. `sections` limits the answer; structure members and filter values that appear as BW-internal ids are marked as such.
- **A folder at once** — `afo_scan_workbooks` profiles every workbook of a folder and adds what reading them one by one does not give: which query, planning function and variable is used in which workbooks, recurring layouts (the same aliases bound to the same queries), and outliers (another system or AfO version than the majority, unreadable files, files without an AfO definition). Above 50 workbooks the answer is compact by default.
- **Where a name is used** — `afo_where_used` finds every place a technical name occurs across a folder: query or InfoProvider, alias, planning function or sequence, aggregation level, planning filter, variable in prompts, planning objects, cell references and `SAPGetVariable`, characteristic in filters and axes, SAP formula arguments, and VBA code.

### Added — Build

- **Workbooks from a spec** — `afo_build_workbook` writes data sources with stored prompts, axes and input readiness, crosstabs, planning functions with aggregation level, fixed filter values, stored variables and variables read from cells, VBA modules, document modules for event handlers, and button macros. The base is a layout template, an existing AfO workbook, or a generated minimal layout. The spec is checked as a whole first and every problem is reported at once; the result is read back and broken links are returned.
- **A new layout for an existing workbook** — with `source`, every entry with `from` is taken over verbatim from the source workbook: a data source with its whole stored state (filters incl. hierarchy nodes, display settings, design rules, exceptions, conditions, prompts), a crosstab with its settings, a planning function or sequence with variables, filter and references, a filter component with its formula. Keys may be renamed and references follow; the connection (SAProuter, SNC) and the workbook settings come from the source unless the spec sets them. Verified element by element on 30 real workbooks; the rebuilt workbooks open and refresh in Analysis for Office.
- **Input readiness of taken-over data sources** — `inputReady` on an entry with `from` switches the data source input-ready (or not) in the new layout; everything else of its stored state stays.
- **Crosstabs that keep the layout** — `autoFit: false` on a crosstab stops AfO from adjusting the column widths on refresh, so cards and buttons above it stay where the layout put them.
- **Planning functions bound to their data source** — `deltaMode` processes changed data only, and `filterFromDataSource` takes the filter of the listed characteristics from the data source at execution time, so a filter on the crosstab restricts the function too.
- **Formatting rules per structure member** — `designRules` on a data source writes Analysis formatting rules (Design, Format Cells) into its stored state: a cell style per structure member, own styles with background and font colour or AfO predefined ones, for the member and its data cells (`BOTH_AREAS`), the data cells only (`LAST_AREA`) or the member cell only (`FIRST_AREA`). Own styles need an Excel cell style of the same name in the layout; Excel drops custom styles with underscores in the name on save, so use spaces.
- **VBA from the source** — standard and document modules taken over from the source workbook, with text replacements for moved cells or renamed keys.
- **Cells, filter components and style set** — `cells` writes values and SAP formulas into the template (stored with the add-in prefix AfO expects), `formulaItems` adds filter components, `styleSetName` names the style set whose `SAP*` cell styles draw the crosstabs.
- **Hierarchies on open** — `hierarchies` on a data source shows a BW hierarchy on a characteristic with the levels expanded (`drillLevel`, 1 = top nodes only), `compactRows` the compact display of rows (the characteristics in the rows as one tree). Both are written into the stored state as Analysis for Office saves them, in `afo_build_workbook`, `afo_quick_report` and `afo_update_workbook`; there, nodes opened or closed by hand are reset for that characteristic. Switching a hierarchy on has no AfO API function, so this is the way to a workbook in which an agent navigates with `EXPAND` and `DRILLLEVEL`.
- **Stored filters** — `filters` on a data source writes filters into its stored state: single members, hierarchy nodes (`nodes`, text nodes or value nodes, with the hierarchy in `hierarchies`), intervals, comparisons (`>`, `>=`, `<`, `<=`), each included or excluded; several entries for one characteristic combine. `afo_quick_report` takes them too. Analysis for Office takes them over as the data source's effective filters.
- **Templates from other tools** — a layout workbook written by openpyxl and similar libraries (relationship attributes in another order, the relationships prefix declared per sheet, an empty `<definedNames/>`) is accepted as template; Excel used to reject the result.
- **Connection with SAProuter and SNC** — `system` takes `sapRouter`, `sncPartnerName` and `sncQuality`.
- **Keep the data on save** — `removeDataOnSave: false` turns off AfO's *remove data before saving*, so a saved workbook shows its last result without a logon.
- **Change instead of rebuild** — `afo_update_workbook` stores variable values (the workbook then opens in that selection without the prompt dialog), adds planning functions, retrofits the agent bridge and adds VBA modules, keeping layout, data sources, crosstabs and existing macros. The VBA project is patched, not replaced; existing `Workbook_Open` and `Workbook_SheetCalculate` handlers get one call added. A data source with *reset data source* gets it switched off, since AfO would drop the stored values on open.
- **Another system** — `afo_update_workbook` with `system` points every data source and planning object to another system: development to quality to production, or after a system move. The connection comes from the SAP Logon landscape of the machine (server, system number, SAProuter, SNC) or from a reference workbook; client and language stay unless given.
- **AfO workbooks as template** — a workbook AfO saved itself, such as one fetched from BW, is accepted as template: its definition is replaced, its sheets keep their AfO ids, and each sheet keeps a single `customProperties` element.

### Added — Agentic planning

- **The agent bridge** — a bridge sheet with a command cell through which Claude in Excel works in an AfO workbook. Office.js writes raise no `Change` event, so Analysis for Office ignores values an agent writes into cells; the bridge turns a command into VBA that writes as a user does and calls the AfO API. Commands: `SET`, `TRANSFER`, `PLAN`, `PVAR`, `VAR`, `FILTER`, `REFRESH`, `SAVE`, `RESET`, `API` (any AfO API function except the logon) and workbook commands that run a macro. New AfO messages are logged after every step and an error fails it; a disabled `PlanDataTransfer` or `Reset` counts as nothing pending. The sheet carries the help with rules for agents and live lists of data sources, planning objects and messages, and is hidden by default.

- **Filters an agent can actually set** — the bridge takes commands one per line, so a value may contain ";" and `FILTER DS_1 DIM=a;b;c` sets several members at once; `FILTER … =@Sheet!A1:A50` takes the keys from a range; `FILTERWHERE DS_1 DIM "Key figure" >= 100000` filters a characteristic to the members whose crosstab value meets a condition, as a real Analysis for Office filter that survives refresh; `UNFILTER DS_1 DIM` lifts it. The first rule on the bridge sheet now forbids Excel means (AutoFilter, sorting, hiding, formulas) on crosstabs.
- **More bridge commands** — `SETDATA DS_1 Key figure|DIM=key;…|value` writes a plan value by member combination through the AfO formula `SAPSetData`, wherever the crosstab shows it; `NEWLINES Crosstab1 n` opens new lines for member combinations the crosstab does not show yet, filled with `SET` (a value in quotes is written as text, as are values with a leading zero); `CHANGEMODE` and `DISPLAYMODE` switch an input-ready data source; `MOVE DS_1 DIM=ROWS|COLUMNS|FREE|AFTER X|BEFORE X|SWAP X` moves characteristics; `FILTER` and `UNFILTER` also take a planning function or sequence. While commands run, AfO's message window is off, so a message cannot stop a command; the messages go to the log. A step AfO fails without a message now says so.
- **Hierarchy navigation** — `EXPAND DS_1 node` and `COLLAPSE DS_1 node` open and close a hierarchy node in the crosstab, the node given by key, by text as shown or by its cell; `DRILLLEVEL DS_1 DIM=n` shows a hierarchy in the rows down to level n. They work for BW hierarchies and for the compact display of rows. The Analysis for Office API has no function for hierarchies, and AfO takes the position of a click on a node from the mouse pointer, so the bridge puts the pointer on the node symbol for a moment, clicks and puts it back; the Excel window must not be minimized. Switching a hierarchy on or off still comes from the query or the state saved with the workbook.
- **A skill for Claude in Excel** — `skills/afo-agent-bridge` teaches the agent to find the bridge, run commands, read results and stay away from Excel features in AfO workbooks. Upload it in Claude's settings; skills enabled there apply in the Excel add-in too.

### Added — Operate

- **Open a workbook logged on** — `afo_open_workbook` starts Excel outside the server's process tree, logs on with `SAPLogon`, refreshes once to initialise the data sources, sets variable values with `SAPSetVariable`, refreshes with them and saves on request. Excel stays open for the user. While Excel shows the security bar, Analysis for Office refuses the logon; the tool retries for a while so the user can enable the content.
- **Workbooks that refresh on open** — such a workbook asks for its own AfO logon while it loads, before `SAPLogon` can run, and its data sources stay inactive. When logging on, `afo_open_workbook` opens a working copy with refresh on open off and names it in `notes`; `keepRefreshOnOpen` opens the workbook as it is. `afo_update_workbook` switches the setting with `refreshOnOpen`.
- **Ad-hoc reports** — `afo_quick_report` writes a plain `.xlsx` with one or more queries (`reports`, one crosstab and sheet each, optionally on a layout workbook, `template`) and the variable values stored, connected as the SAP Logon landscape of the machine describes the system (server, system number, SAProuter, SNC name), and opens it logged on with the data. Without macros there is no security bar, so the logon runs without the user.
- **No silent waiting on dialogs** — when Excel or AfO waits on a dialog (prompt dialog for a mandatory variable without value, AfO logon, message box, repair or file-in-use prompt), `afo_open_workbook` and `afo_quick_report` stop after about 20 seconds without progress and report the dialog with title, text and buttons, instead of running into their 15-minute timeout. The dialog stays open in Excel for the user; nothing is clicked.
- **Logon per system without passwords in the conversation** — `AFO_LOGON_SYSTEMS` lists one logon per system. With a secret runner (`AFO_SECRET_COMMAND`, any command that starts a process with the secrets of an entry in its environment) the logon runs in a short-lived child process and the server itself never holds a password; credentials never pass through tool arguments.
